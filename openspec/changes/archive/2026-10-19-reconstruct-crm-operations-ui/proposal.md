## Why

The existing minimalist shell does not yet provide a complete, documented operational experience across the CRM. Long setup forms precede the records people manage, navigation groups technical configuration alongside daily work, and module-level parity and browser evidence are incomplete.

## What Changes

- Inventory actual routes, screens, permissions, dependencies and regression risks before changing presentation.
- Evolve the existing dual-theme Blade design system using current Taste app-screen guidance and Impeccable review.
- Group destinations by operational task while retaining backend role checks and existing named routes.
- Make management lists primary and reveal creation forms on demand, reopening them after validation errors.
- Organize email preparation, templates, review and delivery into clearly labelled stages without changing delivery rules.
- Refine dashboards, shared tables, forms, settings and the agent workspace while preserving mounted telephony and form state.
- Validate with automated regression tests and isolated synthetic browser fixtures; document external-service limits honestly.

## Capabilities

### New Capabilities
- `crm-operations-workspace`: Task-oriented navigation, record-first management, accessible shared presentation, and explicit email workflow stages.

### Modified Capabilities
None. Existing authentication, reporting calculations, campaign scope, delivery controls and telephony contracts remain in force.

## Impact

Blade layouts/components/module views, presentation CSS, navigation support, regression tests and documentation. No database migration, route rename, external API contract, production operation or new product dependency. Skill installations are development guidance only.
